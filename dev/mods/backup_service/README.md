# backup_service

Бэкапы мира сервера в формате SBK (перенесён из [SimpleBackups](https://github.com/ChaoticTrials/SimpleBackups), Apache 2.0).

## Как это работает

Каждый день в заданное время мод делает бэкап:

- в день полного бэкапа (по умолчанию воскресенье) — **полный**, весь мир: `full-2026-10-04_03-00-00.sbk`;
- в остальные дни — **дифференциальный**, только файлы, изменённые с последнего полного: `diff-2026-10-09_03-00-00.base-2026-10-04_03-00-00.sbk`. Часть `base-…` в имени — это полный бэкап, без которого diff не восстановить.

Если полного бэкапа нет или ему уже неделя (например, сервер был выключен в воскресенье), вместо diff делается полный.

После каждого бэкапа старые удаляются. Остаются все бэкапы за последние 7 дней, 4 последних полных и полные, на которые ссылаются оставшиеся diff.

Бэкап, пропущенный из-за выключенного сервера, при запуске не догоняется: следующий будет в ближайшее время по расписанию. На время бэкапа автосохранение мира приостанавливается. Если сервер останавливают во время бэкапа, он сначала дожидается его окончания.

## Копии в S3

Каждый бэкап дублируется в S3-хранилище (MinIO, Versity Gateway и другие S3-совместимые). На диске сервера всё остаётся как было.

- Отправка идёт в фоне после бэкапа и не задерживает сервер. Файлы больше 32 МБ грузятся частями. Объект появляется в бакете, только когда загружен целиком.
- Если хранилище недоступно, бэкап остаётся на диске, а в лог пишется ошибка. Всё, чего нет в бакете, досылается после следующего бэкапа, при запуске сервера или по команде `backup upload`.
- В бакете действует та же ротация (7 дней + 4 полных), но по собственному списку файлов. Если удалить бэкап с диска вручную, из S3 он не пропадёт.
- Мод трогает только файлы бэкапов (`full-…`, `diff-…`) в своей папке бакета, остальное не трогает.

Включение: в `config/backup_service-common.toml` в разделе `[s3]` впишите `accessKey` и `secretKey` и поставьте `enabled = true`. Ключу нужны права на чтение списка, загрузку и удаление объектов в бакете. Не коммитьте этот файл с ключами.

## Команды

В консоли сервера (или в игре с правами оператора уровня 4):

| Команда | Что делает |
|---|---|
| `backup` | Когда следующий бэкап по расписанию |
| `backup create` / `backup create full` | Полный бэкап сейчас |
| `backup create diff` | Diff от последнего полного сейчас |
| `backup list` | Список бэкапов и их размеры |
| `backup upload` | Дослать в S3 всё, чего там нет, и почистить старое |

## Настройки

`config/backup_service-common.toml`:

| Параметр | По умолчанию | |
|---|---|---|
| `schedule.enabled` | `true` | Бэкапы по расписанию |
| `schedule.time` | `"03:00"` | Время ежедневного бэкапа, часовой пояс сервера |
| `schedule.fullBackupDay` | `"SUNDAY"` | День полного бэкапа: `MONDAY` … `SUNDAY` |
| `retention.dailyDays` | `7` | Хранить все бэкапы за столько дней |
| `retention.weeklyCount` | `4` | Хранить столько последних полных |
| `storage.directory` | `"backups"` | Папка для бэкапов |
| `storage.compressionLevel` | `3` | Сжатие 0–9: выше — меньше файл, дольше и больше памяти |
| `s3.enabled` | `false` | Дублировать бэкапы в S3 |
| `s3.endpoint` | `"http://185.246.118.82:7070"` | Адрес S3 API |
| `s3.region` | `"us-east-1"` | Регион |
| `s3.bucket` | `"shedevrograd-backups"` | Бакет, должен уже существовать |
| `s3.prefix` | `""` | Папка внутри бакета, например `"survival"` |
| `s3.accessKey`, `s3.secretKey` | `""` | Ключи доступа |
| `s3.pathStyle` | `true` | Адресация `host/бакет/файл`; `false` — `бакет.host/файл` |

## Восстановить мир

Нужны Java 21 и `sbk-tool.jar`. Собрать утилиту: `./gradlew :mods:backup_service:sbkTool` (из папки `dev/`), файл появится в `dev/mods/backup_service/build/libs/sbk-tool-<версия>.jar`.

1. Скачайте с сервера нужный бэкап. Если это `diff-…`, скачайте и полный, указанный в его имени после `base-`.
2. Распакуйте в пустую папку:
   ```
   java -jar sbk-tool.jar extract full-2026-10-04_03-00-00.sbk restore
   java -jar sbk-tool.jar extract full-2026-10-04_03-00-00.sbk diff-2026-10-09_03-00-00.base-2026-10-04_03-00-00.sbk restore
   ```
   Первая команда — из полного бэкапа, вторая — из diff. Получится `restore/world`. Утилита проверяет, что diff подходит к полному, и никогда не перезаписывает существующую папку.
3. Остановите сервер.
4. Переименуйте текущий мир на сервере (`world` → `world.old`), не удаляйте его сразу.
5. Загрузите `restore/world` на место мира. Имя папки должно совпадать с `level-name` в `server.properties`.
6. Запустите сервер и проверьте мир. `world.old` удаляйте, только когда убедитесь, что всё в порядке.

`java -jar sbk-tool.jar info <архив>` покажет тип бэкапа и какой полный нужен для diff, `list` — все файлы в архиве.

## Что важно знать

- Сохраняется только папка мира (все измерения, игроки, данные модов). Конфиги, `server.properties` и `ops.json` в бэкап не входят.
- Region-файлы (`.mca`) при восстановлении пересобираются: содержимое чанков то же самое, но побайтово файлы отличаются от исходных. Игре это не мешает.
- Diff сравнивает файлы целиком: изменили один блок — в diff попадёт весь region-файл с этим блоком.
